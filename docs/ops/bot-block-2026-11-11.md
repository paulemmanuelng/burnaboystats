# Bot block in the request layer, and the firewall steps (for Paul, 11 Nov 2026)

## What the firewall showed (past day, read 11 Nov 07:40 UTC)

- 79.3k requests: 27.5k allowed, 37.5k challenged by Bot Protection, 13.6k denied.
- /compare drew 63.4k of them.
- The "/compare 60 per minute per IP" rate limit hit 0. The crawl is spread
  over many IPs, so a per-IP limit never fires.
- Most of it wears an ordinary Windows Chrome/150-154 user agent.

## What the code now blocks (proxy.ts, app/lib/botBlock.ts)

Next 16 runs `proxy.ts` (it used to be called middleware) before every page.
It answers **403** (a one-word plain-text body, `Cache-Control: no-store`) to:

1. **The crawlers robots.txt closes the whole site to**: Bytespider,
   TikTokSpider, Baiduspider, Sogou, 360Spider, HaosouSpider, YisouSpider,
   PetalBot, ChatGLM-Spider. The list comes from `CLOSED_CRAWLERS` in
   `app/robots.ts`, so one edit there changes both.
2. **Scripts, scrapers and headless browsers**: HeadlessChrome, Lightpanda,
   Reflectionbot, PhantomJS, python-requests, aiohttp, httpx, Python-urllib,
   Go-http-client, Scrapy, curl, Wget, axios, node-fetch, undici, okhttp,
   Java/, Apache-HttpClient, libwww-perl, SERankingBacklinksBot.
3. **Any self-declared crawler on a /compare URL with a query string**, which
   robots.txt already disallows. That includes Googlebot and GPTBot on those
   URLs only. The link-preview fetchers (WhatsApp, facebookexternalhit,
   Facebot, Twitterbot, TelegramBot, Discordbot, LinkedInBot, Slackbot,
   Pinterestbot) are exempt, because they fetch the exact link someone shared.

Allowed requests to /compare with a query string also get
`X-Robots-Tag: noindex`, so polite crawlers drop the variants.

**Never blocked:** real browsers; search engines and the AI crawlers on the
robots.ts allowlist on every normal page; link previews; our own scripts
(their user agent names burnaboystats); and, because the proxy does not run
on them at all, `/api/*`, robots.txt, sitemap.xml, rss.xml, llms.txt, share
cards (opengraph-image, twitter-image), icons, `/_next/*` and every file with
an extension.

## What the code cannot block

A bot that sends an ordinary Chrome user agent looks exactly like a reader
to the code. That is most of this crawl (the Windows Chrome/150-154 rows, the
Alibaba, Huawei and Google Cloud networks). Only the firewall can see the
network (ASN) and the TLS fingerprint (JA4), so the rest is dashboard steps.

## The dashboard steps

Vercel → the burnaboystats project → **Firewall**. Do not change Bot
Protection (stays **Challenge**) or AI Bots (stays **Allow**).

1. **Deny Huawei Cloud.**
   - Open **Traffic**, last 24 hours, and find the "Huawei Cloud Service data
     center" row in the AS name list. Read its **ASN number** off the row (the
     4 Nov inventory listed AS136907; there may be more than one Huawei row,
     such as AS55990).
   - Rules → **Add Rule**. If **ASN** is (each Huawei number you read) →
     **Deny**. Name it "Block Huawei Cloud".
2. **Deny or challenge the two non-browser TLS fingerprints.**
   - The two JA4 digests are `t13d141000_cbb2034c60b8_e7c285222651` (6.4k; it
     offers no ALPN, so it is not a browser) and
     `t13d1011h2_61a7ad8aa9b6_3fcd1a44f3e3` (5.2k).
   - **Check first.** Open **Explore query** (or click the digest in Traffic)
     and filter by each digest. Look at the AS names behind it. If it comes
     from data-centre networks (Alibaba, Huawei, Tencent, Google Cloud, AWS,
     DigitalOcean and the like) and **not** from MTN, Airtel, Glo, Orange,
     Safaricom, Vodacom or other home and mobile networks, it is safe to deny.
     If real mobile networks show up, use **Challenge** instead of Deny.
   - Rules → **Add Rule**. If **JA4 Digest** is either digest → **Deny** (or
     **Challenge**). Name it "Block non-browser TLS".
   - Do **not** touch `t13d1517h2_8daaf6152771_cb7bf5808d99` (40.1k). That is
     ordinary Chrome, readers included.
3. **Optional: challenge /compare variants.**
   - Rules → **Add Rule**. If **Request Path** equals `/compare` AND **Query**
     (or "Raw query") is not empty / exists → **Challenge**. Name it
     "Challenge /compare variants".
   - Readers on a shared /compare link see a one-second check once; headless
     bots mostly fail it. The plain /compare page and every pair page stay
     unchallenged.
4. **Order.** Drag the new rules **above "Allow link previews"**. That rule is
   a Bypass, and a Bypass skips every rule below it, so a bot faking a preview
   agent would skip anything placed under it. From the top, the order becomes:
   "Rate limit /compare to 60/min per IP", "Block Lightpanda", "Block Alibaba
   Cloud", "Reflectionbot", "Block Huawei Cloud", "Block non-browser TLS",
   "Challenge /compare variants" (if added), then "Allow link previews".
5. **Save, then check.**
   - burnaboystats.com, /compare and a pair page still load on your phone
     (on mobile data and on Wi-Fi).
   - A WhatsApp link preview of a /compare link still shows its card.
   - The next day: Traffic's denied count rises and the /compare total falls.

"Block Lightpanda" and "Reflectionbot" can stay. The code now blocks both too,
but the firewall stops them before they cost a function call.
